# orangehrmdemo2 – Playwright test framework

Generated by Requirement Analyzer (template `requirement-analyzer-playwright` 1.1.0). Tests are written
by the app's Script Author agent and by people, following the conventions below.

## Run

```
npm ci
npx playwright install chromium
TEST_ENV=qa RA_ACCOUNTS='{"Admin":{"username":"…","password":"…"}}' npx playwright test
npx playwright test --grep @smoke          # only the smoke tests
npx playwright test --grep @TC-1023        # the tests of one manual test case
BROWSERS=chromium,firefox,webkit npx playwright test   # more browsers (after: npx playwright install firefox webkit)
```

Environments: `qa` (https://opensource-demo.orangehrmlive.com/web/index.php/auth/login) (files in `config/environments/`, checked at start-up: a missing or mistyped setting stops
the run with a clear message). Logins come from `RA_ACCOUNTS` (a CI secret), never from the code or the data files.

| Setting | Values |
|---|---|
| `TEST_ENV` | An environment file name, without `.env.json` |
| `BROWSERS` | `chromium` (default), `firefox`, `webkit`, `mobile-chrome`, `mobile-safari`, comma separated. WebKit and the mobile projects are emulations: real Safari and real phones come from a cloud grid |
| `EXECUTION_MODE` | `local` (default) or `cloud` (see *Cloud grid*) |
| `RUN_QUARANTINE` | `1` also runs the `@quarantine` tests, which CI leaves out of the blocking run |

If the site's test ids use another attribute than `data-testid` (e.g. `data-test`), set `"testIdAttribute": "data-test"`
in the environment file; `getByTestId` then reads it.

## Structure

| Folder | What lives there |
|---|---|
| `config/` | Environments (`TEST_ENV`) and shared constants such as timeouts |
| `src/locators/` | Every locator, once, per page or component |
| `src/pages/` | Page objects: business actions (`login`, `createOrder`) and `expect*` checks |
| `src/components/` | Widgets used on several pages (tables, date pickers, modals) |
| `src/fixtures/` | `test`, `expect`, `step`, `account`: the only import of a spec. `ra/` is managed by the app |
| `src/data/<env>/` | Test data per environment; `${NAME}` placeholders are filled from environment variables |
| `src/data/factories/` | Fresh values for every run (new users, unique names) |
| `src/api/` | API helpers for setup and teardown |
| `src/execution/` | Where the browser runs: local, or a cloud grid (one file per provider) |
| `src/utils/` | Data loader, logger (hides passwords, tokens and keys) |
| `tests/<module>/` | Specs, one file per feature, grouped with `test.describe` |
| `traceability/` | Manual test case id ↔ spec and test title |

## Conventions (checked by `npm run lint` where possible)

1. Never write a locator in a spec or a page object: all locators live in `src/locators/`.
2. Never hard-code test data or credentials: data goes to `src/data/<env>/`, logins come from `account('<name>')`.
3. Specs import `test` and `expect` only from `src/fixtures`.
4. Page object methods represent user intent; assertions only in `expect*` methods.
5. Prefer `getByTestId` (when the element has a test id) → `getByRole` → `getByLabel` → `getByText`; justify any
   CSS or XPath in a comment, and any positional locator (`nth`, `first`, `last`), used only when nothing else tells
   the element apart. Test ids survive wording and translation changes; ask the developers to add them where they
   are missing.
6. No `page.waitForTimeout()` and no `page.pause()`: rely on auto-waiting and web-first assertions. Every promise is
   awaited (lint finds a forgotten `await`).
7. Every test title starts with the manual test case id and carries an `@TC-<id>` tag, e.g.
   `test('TC-1023: Valid user can log in @smoke @TC-1023', …)`.
8. Change existing files minimally; never delete or rename existing members without approval.
9. Each test-case step is one `step(page, '<n>. <step>', …)`, so results show every step with a screenshot.
10. Never commit `test.only`, and never switch a failing test off (`test.fixme`, an unconditional `test.skip`) to get a
    green build: fix it, or quarantine it (below). `test.skip(condition, 'reason')` for a real limit (e.g. a browser
    the feature does not support) is allowed.
11. Tricky parts get one shared way of handling them, in a component or page object: frames with `frameLocator`, new
    tabs with `context.waitForEvent('page')`, downloads with `page.waitForEvent('download')`, uploads with
    `setInputFiles`, dialogs with `page.on('dialog')`, date pickers by typing an ISO date where the widget allows it.

## Flaky tests and quarantine

Re-runs collect evidence: in CI a test is retried once, and one that passes only on the retry is reported as
**flaky**, not passed. Fix the cause (a fixed wait, shared data, a test that depends on another). If the fix takes
longer, a person may quarantine the test, never the AI agent:

```ts
test('TC-1023: Valid user can log in @TC-1023 @quarantine',
  { annotation: { type: 'quarantine', description: 'owner: Ann; ticket: QA-512; until: 2026-12-15' } },
  async ({ page }) => { … });
```

CI leaves quarantined tests out of the blocking run and runs them in a separate step that reports but never blocks.
Lint fails when the owner, ticket or end date is missing, and once the end date has passed. Remove `@quarantine` when
the test has passed reliably again.

## CI (GitHub Actions)

`.github/workflows/playwright.yml` runs the type check, lint and all tests on every pull request, on every push to
`main`, and on demand (**Actions → Playwright tests → Run workflow**, where you can pick the environment).
Set up once in the repository's **Settings → Secrets and variables → Actions**:

| Kind | Name | Value |
|---|---|---|
| Secret | `RA_ACCOUNTS` | The test logins as JSON: `{"Admin": {"username": "…", "password": "…"}}` (the names `account('…')` uses) |
| Variable | `TEST_ENV` | The environment to test, e.g. `qa` (default) |
| Variable | `BROWSERS` | Browsers to run, e.g. `chromium,firefox` (default `chromium`) |
| Variable, secrets | `EXECUTION_MODE`, `LT_USERNAME`, `LT_ACCESS_KEY` | Only for a cloud grid (see *Cloud grid*) |

Quarantined tests run in their own step after the tests; its result is shown but never fails the workflow.

The HTML report and test results of each run are kept for 14 days (the run's **Artifacts**). Package versions come
from `package-lock.json` (`npm ci`), the same versions the app checks the framework with.

## Cloud grid

`EXECUTION_MODE=cloud` runs every test in its own browser session on a grid; tests do not change. The provider is
`CLOUD_PROVIDER`:

- `lambdatest` (default; LambdaTest, now TestMu AI): secrets `LT_USERNAME` and `LT_ACCESS_KEY`; optional
  `LT_BROWSER` (`Chrome`, `MicrosoftEdge`, `pw-chromium`, `pw-firefox`, `pw-webkit`), `LT_PLATFORM` (e.g.
  `Windows 11`), `LT_TUNNEL_NAME` for a site that is not on the internet (start the LambdaTest tunnel in a CI step
  before the tests and stop it afterwards). Each session gets the test's name and its pass or fail status.
- `selfhosted`: a Playwright server (`npx playwright run-server --port 3000`, same Playwright version) at
  `PW_WS_ENDPOINT`, e.g. `ws://playwright-server:3000/`.

Before relying on the grid, try each feature the tests need there (traces, downloads, file uploads) in a small trial
run: not everything behaves as it does locally. Keep `@playwright/test` at a version the grid supports. Provider
details live only in `src/execution/`, so changing provider touches one file.

## Requests to other sites

`src/fixtures/ra` blocks every request to a host that is not in the environment's `allowedHosts`, so a test never
reaches a site it should not. Add a host to the environment file when the site really needs it.
